## Inputs

- Photos: `pics/` (DSC01768.JPG, DSC03127.JPG, DSC03127 2.JPG [duplicate], DSC03212.JPG). Originals are 7–11 MB: downscale copies (e.g. `sips -Z 1600`) into the site's `public/`, never ship the originals.
- Privacy: do NOT publish the phone number or home address from the CV. Use name, role, skills, experience, and a contact link/placeholder (email to be confirmed by the user).

## Goal
Build a premium, highly animated personal portfolio blog using a static Next.js + React export hosted free on GitHub Pages. It must compile to flat static files (`output: 'export'`), have a polished UI with smooth animations, parse resume-style content from local Markdown files, and render a Pixar-style animated avatar slot in the hero.

## Team
Create a team called **static-resume-blog** with 3 teammates using **Sonnet**, in **split panes (tmux)** mode. Name them `designer`, `frontend-dev`, `qa`.

### designer
Design a premium developer portfolio optimized for dark/light themes. Provide clear typography scales and layout grids for sections tracking the resume (Hero, Experience, Projects, Blog). Outline animation choreography (hover states, section entrances, page layout transitions) matching Framer Motion capabilities. Designate a high-visibility placeholder spot in the Hero for the Pixar animated version of the photo. Message `frontend-dev` when the visual spec is ready. Owns: `design/`.

### frontend-dev
Bootstrap a Next.js project with Tailwind CSS and Framer Motion. Configure `next.config.js` for static export (`output: 'export'`) with unoptimized images for GitHub Pages. Replicate the resume content into modular components: Hero, ExperienceTimeline, ProjectsGrid, BlogRoll. Build the blog engine to parse and render posts from local Markdown/MDX files (no server runtime). When done, verify static compilation places production assets correctly in `out/`, and message `qa` stating "frontend complete". Owns: everything outside `design/`, `tests/`, `.github/`, and `docs/deployment-guide.md`.

### qa
Prepare a validation strategy in `tests/static-validation.md` focused on relative asset paths (no broken images/links on GitHub project subpaths) and mobile responsive scaling. Once frontend-dev passes the code, verify the static output by serving the compiled `out/` directory locally (also test under a simulated `/<repo-name>/` subpath). Write `.github/workflows/deploy.yml` that builds and deploys via GitHub Actions. Document findings in `tests/validation-report.md` with pass/fail remarks and notify the team lead when done. Owns: `tests/`, `.github/`.

## Final deliverables
- Static Next.js codebase optimized for client-side routing and animation playback
- `.github/workflows/deploy.yml`
- `tests/validation-report.md`
- `docs/deployment-guide.md` (asset path setup: basePath/assetPrefix, and launch steps) — lead writes this after QA reports, or assigns it to frontend-dev

## Lead rules
- Make basePath configurable via env (e.g. `NEXT_PUBLIC_BASE_PATH`, set from the repo name in the workflow) so one build config works for both user-site and project-site hosting.
- Tell teammates to wait for dependencies (spec → frontend → QA). Do not implement yourself; wait for teammates and synthesize.
- Pre-approve common npm/node/sips/curl commands before spawning to cut permission prompts.
- The Pixar avatar cannot be generated by the team; leave a clearly-marked swappable slot (with the cropped real photo as temporary fallback).
